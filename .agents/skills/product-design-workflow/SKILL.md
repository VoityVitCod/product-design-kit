# От поручения к проверяемой правке

[Рабочие договорённости](../../../design/WORKING-AGREEMENT.md) описывают формат результата и работу с короткими уточнениями. Правила продукта берутся из его макетов и [карточки проекта](../../../design/PROJECT-STANDARDS.md). Для начала достаточно ссылки на рабочий объект и понятного изменения.

## Выбери точку входа

| Запрос | Что сделать |
| --- | --- |
| Изменить один элемент | Открой точный узел и экран целиком. Сверь экземпляр с образцом того же состояния. Измени нужное свойство. Сравни результат в рабочем масштабе. |
| Пересобрать несколько экранов | Определи множество экранов по указанной области и уровню детализации. Учитывай отдельно лежащие копии. Перед массовой заменой проверь один сложный случай. |
| Добавить сценарий | Определи вход, действие, обратную связь и возврат. Проверь, что выбор сохраняется и влияет на итог. Учитывай отмену или повторное действие, когда они относятся к задаче. |
| Сделать визуал | Соблюдай заказанный формат. «Нарисуй» ведёт к рисунку, «в Figma» — к редактируемому объекту, «в Figma Slides» — к слайдам. «Дай список» обычно можно выполнить в чате. |
| Провести ревью | Дай отдельным рецензентам один и тот же снимок или версию прототипа. В поручении «оцени» верни выводы. Если также запросили исправление, внеси подтверждённые правки и проверь их. |

Если во время работы поступило уточнение или макет изменился вручную, сверяй живой узел ещё раз. Сохраняй одобренные части. Для операций в Figma используй доступное подключение с правами на нужный файл и применимые инструкции среды. Для правки одного экземпляра сначала попробуй его свойства. Общий компонент меняй, когда это соответствует запрошенному охвату.

## Распредели задачи

Основной агент отвечает за результат. Для небольшой правки он может выполнить всё самостоятельно. Для сложной подходит один редактор макета и несколько специалистов, которым можно дать независимые вопросы.

- `figma_systems` проверяет систему компонентов и последствия изменения мастера.
- `figma_ux` разбирает действия, состояния, возврат и текст.
- `figma_visual` оценивает композицию в нужном размере и выделяет нужное качество референса.
- `figma_qa` получает результат и исходное замечание, затем пытается повторить проблемный случай.

Для полного независимого просмотра запусти пять рецензентов — `visual_hierarchy`, `search_ux`, `brand_review`, `ui_clarity`, `ai_patterns`. Передай каждому контекст, версию и вопрос по его роли. Сначала собери собственные наблюдения каждого. Затем сведи повторы и отсортируй подтверждённые проблемы по тому, как они мешают целевому действию.

Если клиент позволяет выбирать профиль по имени, выбери его. Если он предлагает запуск обычных субагентов, передай каждому отдельному агенту `developer_instructions` из нужного файла в `.codex/agents/`. При ограничении параллельных запусков выполняй поручения очередями. Если в среде вообще нет субагентов, укажи фактическое число участников. [Поручения и формат результата](../../../SUBAGENTS.md)

## Сдай результат

Верни прямую ссылку на изменённый узел, открываемый файл или готовое изображение согласно запросу. Назови, что исправлено и как проверено. При правке переноса посмотри длинное название, при жалобе на сброс выбора пройди возврат. Если доступны только снимки, сообщи, что видно на них. Существенное предположение укажи одним предложением.
